# Сценарий защиты лабораторной

Все команды выполняются из каталога репозитория. В примерах используется запасной диапазон 7101–7104. Если выбран обычный запуск, уберите `-BasePort 7101` и `--base-port 7101`, а интерфейс открывайте на 5102.

## 1. Сборка и обычный турнир

```powershell
dotnet restore MathTournament.sln
dotnet build MathTournament.sln --no-restore
dotnet test tests/Tests.csproj --no-build --logger "trx;LogFileName=tests.trx" --results-directory test-results
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -BasePort 7101
```

Открыть http://localhost:7102. Нажать **«Демо» → «Запустить демонстрацию»**. Показать две команды, две последовательные игры, четыре цвета вердиктов и итог **Интеграл 200 : Квадрат мысли 196**. Настоящие сервисы рассчитывают результаты, тестовый имитатор даёт входные вердикты. Подготовка игр теперь проходит через Saga; сроки решений отсчитываются после её успешного завершения.

## 2. Saga с реальной компенсацией

```powershell
python scripts/lab-demo.py saga --base-port 7101
```

Ожидается `PASS Saga...`. Скрипт создаёт отдельный турнир, сначала резервирует таблицу в сервисе баллов, затем имитатор отклоняет бланки. Пока последний ответ об освобождении задержан, игра находится в `Compensating` и недоступна для повторного старта. Физический резерв таблицы уже имеет состояние `Released`; публичные результаты не созданы. После обоих ответов игра снова `Configured`. Новая попытка имеет другой ID и успешно запускается; поздний ответ старой попытки её не изменяет.

Открыть раздел «Игры» и выбрать созданный `saga-...` в списке турниров. Состояния и попытки доступны также по защищённому `/internal/diagnostics` сервиса турнира и баллов. Для показа вручную: войти как организатор, создать и настроить турнир, зарегистрировать команды от капитанов, начать турнир, в «Играх» нажать **«Учебный отказ бланков»**, затем начать игру. Дождаться освобождения резервов и повторить старт.

Для воспроизводимого реального перезапуска координатора, без остановки рабочего демонстрационного турнира:

```powershell
python scripts/check-lab.py
```

Он поднимает собственные процессы на 7201–7204 и БД в `test-results`, принудительно завершает координатор во время Saga, восстанавливает его и выполняет компенсацию/повтор. Остальные сервисы читают только свои базы; проверка обращается к их API.

## 3. CAP, eventual consistency и сроки

```powershell
python scripts/lab-demo.py cap --base-port 7101
```

Доставка части событий временно приостанавливается на отправителе. Это управляемая модель недоступной связи, а не выключение самого сервиса баллов:

- GET таблицы и SSE продолжают отдавать последний известный публичный снимок.
- Турнир независимо сохраняет закрытие обоих приёмов по срокам, хотя сообщения ещё ждут в outbox.
- После восстановления первого направления баллы и итоги сходятся. Пока подтверждённый итог не дошёл турниру, команда запуска следующей игры получает 409.
- После восстановления оставшейся связи следующая игра доступна, итог турнира — 200/196, повторного начисления нет.

Не маркировать весь проект как «AP» или «CP». Обсуждаются конкретные операции: доступное чтение устаревающей проекции и отказ разрешить переход состояния без подтверждения предыдущего результата. Проверка иллюстрирует компромисс и последующую сходимость, не является формальным доказательством CAP.

## 4. Кеширование

В конце CAP-сценария выполняются повторные GET и чтение SSE. В диагностике сервиса баллов `/internal/diagnostics` видны `cache.hits`, `cache.misses`, `ttlSeconds=10`. Снимки GET и SSE совпадают. Кеш общий для экземпляра сервиса, но ключи разных турниров раздельные.

На защите объяснить: данные и версия снимка записываются в одной SQLite-транзакции; после коммита кеш инвалидируется. Попытка старого запроса повторно положить устаревший снимок не обманывает следующий запрос — он проверяет сохранённую версию. TTL ограничивает жизнь записи. Тесты отдельно проверяют изменение после вердикта, в том числе при нулевых баллах и изменившемся статусе, откат, параллельные чтения и разные турниры.

## 5. Ограниченный детерминизм

```powershell
dotnet test tests/Tests.csproj --filter FullyQualifiedName~DeterminismTests
```

Показать `DeterminismTests`: фиксированные время, входные IDs и факты; 32 порядка доставки, дубликаты, вердикты раньше привязок, победитель раньше итогов. Сравнивается конечная публичная проекция: баллы, статусы, места, очки и завершение. Промежуточные снимки, новые технические IDs исходящих уведомлений и аудит не обязаны совпадать. Условия: одинаковые непротиворечивые факты, корректные конечные манифесты, детерминированная формула, ожидание зависимостей, идемпотентность.

## 6. Учебная модель 2PC

```powershell
dotnet run --project src/TwoPhaseLab/TwoPhaseLab.csproj
```

Ожидаются три сценария:

| Сценарий | Решение | Состояние участников | Балансы |
|---|---|---|---|
| commit | Commit сохранён до отправки | Committed / Committed | 90 / 90 |
| abort | Один участник отказал | Aborted / Aborted | 100 / 100 |
| recovery | Координатор недоступен после Prepare, затем восстановлен | сначала Prepared, затем Committed | сначала 100 / 100, затем 90 / 90 |

Это **учебная модель протокола на прикладных резервированиях SQLite**, не XA/DTC и не распределённая транзакция самой SQLite. Координатор и два участника имеют отдельные файлы; каждый объект открывает только свой. Вызовы выполняются в отдельном консольном примере в одном процессе; недоступность канала решения моделируется явно. Подготовленный участник сохраняет резерв и не выбирает Abort самостоятельно по тайм-ауту. После восстановления повторно читает сохранённое решение. Пример не подключён к турниру.

Отличие: Saga уже закоммитила резерв таблицы, а затем отдельной локальной транзакцией компенсирует его. В модели 2PC окончательное списание не выполняется до Commit; после Prepare участник может блокировать ресурс, ожидая координатора. Ни один из паттернов не обещает отсутствие промежуточных состояний во всех внешних системах.

## 7. Коммиты и завершение

```powershell
python scripts/check-commits.py
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop.ps1
```

Лимит — 50 изменённых файлов в каждом коммите, не 50 файлов во всём проекте. Скрипт проверяет историю и отсутствие генерируемых артефактов. Перед следующим коммитом: `python scripts/check-commits.py --staged`.

На новом компьютере нужны .NET SDK 8 и браузер; Python нужен только для сценариев командной строки. Для браузерной автоматизации дополнительно нужны Chrome/Edge и `websocket-client`. Интернет нужен при первом восстановлении NuGet. Режимы отказа/приостановки включаются локальным `start.ps1`; для отключения: `-DisableLabDemos`. При прямом запуске Host без `ENABLE_LAB_DEMOS=1` эти управляющие маршруты возвращают 404.
