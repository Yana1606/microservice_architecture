# Турнир математических игр

Учебный проект на C# и ASP.NET Core: три микросервиса управляют турниром, баллами и итогами. Веб-интерфейс «Математическая арена» позволяет настроить турнир и посмотреть его прохождение. Отдельный тестовый имитатор поставляет события работы команд, проверок и апелляций.

## Архитектура и стек

| Процесс | Владелец данных и ответственность | Порт по умолчанию |
|---|---|---|
| `tournament` | Регламент, жюри, команды, игры, сроки, Saga подготовки | 5101 |
| `scores` | Результаты задач, применение вердиктов, публичная таблица и её кеш | 5102 |
| `results` | Места, турнирные очки, итоги игр и победители | 5103 |
| `simulator` | Тестовые события team/checking и резервирование бланков для Saga | 5104 |

- **C# 12, .NET 8, ASP.NET Core Minimal API** — REST API и фоновые обработчики.
- **SQLite / Microsoft.Data.Sqlite** — отдельная база каждого процесса, локальные транзакции и SQL-миграции. Сервисы не читают чужие базы.
- **HTTP/JSON, transactional outbox/inbox** — надёжная доставка с повторами, идемпотентность и ожидание зависимостей при нарушении порядка событий.
- **SSE, HTML/CSS/JavaScript** — публичная таблица в реальном времени без отдельного frontend-сервера.
- **IMemoryCache** — кеш снимка по ID турнира с проверкой версии, инвалидацией после коммита и TTL 10 секунд. GET и SSE используют один источник снимков.
- **xUnit, Python-сценарии, Docker Compose, GitHub Actions** — тестирование и воспроизводимый запуск.

Исходники находятся в [src](src), тесты — в [tests](tests). Описание агрегатов, состояний и соответствия шагам процесса: [docs/architecture.md](docs/architecture.md). Контракты событий, их владельцы и анонимность: [docs/integration.md](docs/integration.md).

## Быстрый запуск на другом компьютере: Windows

Нужны **Git**, **.NET SDK 8** и браузер. Для дополнительных проверок нужен **Python 3.10+** с командой `python`. При первом восстановлении пакетов требуется доступ к NuGet. Docker и Node.js для этого способа не нужны.

Клонируйте репозиторий в удобный каталог и выполняйте следующие команды из его корня. Если репозиторий уже скачан, перейдите в существующий каталог.

```powershell
git clone https://github.com/AvdushkinaKsenia/MathTournament.git
cd MathTournament
dotnet restore MathTournament.sln
dotnet build MathTournament.sln --no-restore
dotnet test tests/Tests.csproj --no-build
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1
```

Скрипт сам собирает решение, запускает четыре процесса в фоне и проверяет их готовность. Откройте **[http://localhost:5102](http://localhost:5102)**. Нажмите **«Демо» → «Запустить демонстрацию»**. Создастся новый турнир из двух команд и двух игр. Примерно через 45 секунд ожидается завершение турнира: **«Интеграл» — 200, «Квадрат мысли» — 196**.

Во время демонстрации можно переключаться между командами, играми, таблицей и итогами. Вердикты поставляет имитатор; баллы, очки, сроки и завершение обрабатывают реальные сервисы. Повторное нажатие запускает новый демонстрационный турнир.

Остановка:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop.ps1
```

Базы находятся в `data`, журналы — в `logs`. Данные сохраняются после остановки, миграции применяются автоматически. Скрипт остановки использует записанные PID и время старта процессов. Для отдельного чистого запуска можно **после остановки** переименовать каталог `data`, сохранив прежние данные.

### Если порты заняты

Остановите прежний запуск из этого каталога, затем выберите другой диапазон:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -BasePort 7101
```

В этом случае интерфейс — **http://localhost:7102**, остальные процессы — 7101, 7103 и 7104. Для Python-проверок ниже задайте `$env:MATH_BASE_PORT='7101'`, для браузерной проверки — `$env:MATH_UI_URL='http://localhost:7102'`, а для `lab-demo.py` добавьте `--base-port 7101`. Не запускайте две копии из одного каталога одновременно: они используют одни файлы данных.

## Что доступно в интерфейсе

Начальный режим — **зритель**. Внизу левого меню можно выбрать демонстрационного организатора или одного из двух капитанов. Права проверяет сервер.

| Раздел | Действия и данные |
|---|---|
| Обзор | Состояние турнира, команды, программа, таймеры и краткая таблица |
| Команды | Регистрация капитаном команды ровно из четырёх участников |
| Игры | Создание, изменение и удаление до старта турнира; последовательный запуск, состояние подготовки и компенсации |
| Онлайн-таблица | SSE-обновления, выбор игры, поиск, баллы, места, очки и CSV |
| Итоги | Итоги игр, общий зачёт и победители после завершения |

Цвета ячеек: верно — жёлтый, неверно — красный, удовлетворённая апелляция — зелёный, отклонённая — красный с красной обводкой. Прямая ссылка на турнир: `http://localhost:5102/?tournament=<id>`.

Для ручного прохождения: организатор создаёт турнир, настраивает игры и публикует регламент; два капитана регистрируют команды; организатор начинает турнир и первую игру. Полноценные интерфейсы сдачи решений и работы жюри не входят в эти три сервиса: их интеграции демонстрирует отдельный имитатор.

## Проверки и сценарий защиты

Подробная последовательность показа: **[docs/defense.md](docs/defense.md)**. В этом документе примеры используют порты 7101–7104; основной запуск выше использует 5101–5104.

### Тесты, обычный турнир и API

При запущенных сервисах на портах по умолчанию:

```powershell
dotnet test tests/Tests.csproj --logger "trx;LogFileName=tests.trx" --results-directory test-results
$demoId = 'defense-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
python scripts/demo.py $demoId
python scripts/check-http.py $demoId
```

Ожидается **200:196** и сообщения `PASS`. Скрипт проверяет две команды, две последовательные игры, апелляции, повторы и обратный порядок событий. Следующая проверка подтверждает OpenAPI, SSE, страницу, анонимность публичных данных и защиту входящих событий. Для каждого нового HTTP-сценария нужен новый ID турнира.

### Критерии

```powershell
python scripts/lab-demo.py all
python scripts/check-lab.py
dotnet test tests/Tests.csproj --filter FullyQualifiedName~DeterminismTests
dotnet run --project src/TwoPhaseLab/TwoPhaseLab.csproj
python scripts/check-commits.py
```

| Критерии | Реализация |
|---|---|
| Saga с компенсацией | Сервис баллов резервирует таблицу, затем имитатор отклоняет бланки. Компенсация освобождает локальные резервы; до обоих подтверждений повтор запрещён, затем новая попытка успешно запускается |
| Восстановление Saga | `check-lab.py` поднимает изолированные процессы на 7201–7204, принудительно завершает и перезапускает координатор на сохранённой БД, проверяет компенсацию и повтор |
| Кеширование | Совпадающие снимки GET/SSE; счётчики `cache.hits`, `cache.misses` и TTL в защищённом `/internal/diagnostics` сервиса баллов |
| CAP / eventual consistency | При паузе доставки таблица доступна с последними данными, сроки обрабатываются независимо. Следующая игра ждёт подтверждённого итога; после восстановления доставки данные сходятся без повторного начисления |
| Ограниченный детерминизм | Тест сравнивает конечные проекции для 32 порядков фиксированных фактов, включая дубликаты, ранние вердикты и раннее событие победителя |
| Учебная модель 2PC | Отдельная консольная программа показывает Prepare → Commit/Abort, сохранение решения, восстановление и ожидание решения при недоступном координаторе |

2PC **не включён в процесс турнира**. Это учебная модель прикладного резервирования: координатор и два участника с отдельными SQLite работают в одном консольном процессе. Это не XA/DTC и не распределённая транзакция SQLite. В Saga уже выполненные локальные изменения отменяются компенсациями; в модели 2PC подготовленные резервы ждут общего решения.

CAP-сценарий моделирует недоступный канал паузой доставки на отправителе. Он показывает доступное чтение устаревающей проекции и ограничение команды старта следующей игры; всему проекту не присваивается общая метка AP или CP.

Управляемые отказы и паузы требуют `ENABLE_LAB_DEMOS=1` и авторизации. Локальный скрипт включает этот режим. Для запуска без этих управляющих маршрутов используйте `scripts/start.ps1 -DisableLabDemos`. Резервы подготовки не появляются в публичной таблице до `GameStarted`; при компенсации интерфейс показывает состояние отмены.

### Дополнительная проверка браузера

При запущенных четырёх процессах, установленном Chrome/Edge и Python:

## Docker Compose

Альтернативный запуск требует Docker Engine и Compose v2; на Windows подойдёт Docker Desktop. При использовании только контейнерного запуска .NET SDK на компьютере не нужен. Python нужен, если запускаются внешние проверочные сценарии.

```powershell
docker compose up --build --wait --wait-timeout 180
docker compose --profile test run --rm tests
```

Откройте **http://localhost:5102** и запустите «Демо». Для HTTP-проверок применяются те же команды и порты, что в основном запуске. Не занимайте их одновременно локальным и контейнерным запуском; если ранее меняли `MATH_BASE_PORT` или `MATH_UI_URL`, верните значения 5101 и `http://localhost:5102`.

```powershell
docker compose logs
docker compose down
```

У каждого процесса свой именованный volume. `down` сохраняет данные. На машине фактической проверки Docker Engine отсутствовал: контейнерная сборка и запуск **не проверены**. В [GitHub Actions](.github/workflows/lab-ci.yml) настроены сборка, тесты, проверка коммитов и Compose-сценарии; их результат нужно смотреть отдельно после отправки коммитов в GitHub.

## Регламент демонстрации

Исходные источники не определяют формулу баллов задач, значения модификаторов и правило ничьих. Подтверждение их отдельного согласования в репозитории отсутствует. Ниже явно зафиксирован регламент существующей учебной демонстрации:

- Верное решение: настроенная стоимость задачи × модификатор бланка; неверное: настроенные баллы за неверный ответ × модификатор. В демонстрации это 10 и 0.
- Бланки: `normal` ×1, `enhanced` ×1.5, `risk` ×2. Стоимость и модификаторы задаются в `GameConfig`.
- При равенстве игровых баллов — места **1, 1, 3** и одинаковые очки за равные места. При равенстве суммы турнира — совместные победители (`SharedCompetition`).
- Турнирные очки за игру: **`100 − 2 × (место − 1)`**.
- Удовлетворённая апелляция заменяет результат; отклонённая сохраняет баллы. Повтор события не начисляет очки повторно.

Реализация поддерживает только `SharedCompetition`; произвольный текст регламента не переключает алгоритм. Перед использованием для реального турнира формулу, стоимости, модификаторы и правило ничьих необходимо согласовать с организатором до публикации. Текущие расчёты и демонстрация 200:196 сохраняются.

Итог игры разрешён после закрытия обоих приёмов, завершения проверок и апелляций и применения всех изменений согласно конечным манифестам. Победители определяются после итогов всех игр и начисления каждой команде очков за каждую игру.

## API, конфигурация и данные

[OpenAPI](docs/openapi.json) также доступен через `/openapi.json` трёх основных сервисов. Маршруты распределены по ролям: не каждый маршрут доступен на каждом порту. Пример тела создания турнира: [demo/tournament.json](demo/tournament.json); для нового турнира измените ID, даты и параметры.

Команды управления турниром требуют `Authorization: Bearer <токен>` и `Idempotency-Key`; для изменения существующего турнира требуется `If-Match` с актуальной `Revision` из организаторского GET. Ошибки возвращают HTTP-статус и предметный код `{ "code": "..." }`. Контракты и ограничения описаны в [docs/integration.md](docs/integration.md).

Демонстрационные токены: `organizer-demo`, `captain-a-demo`, `captain-b-demo`. Организатор меняет только собственный турнир; капитан регистрирует свою команду и входит в её четыре уникальных участника. Публичные данные не содержат эталоны, составы участников и приватные связи решений. Для жюри предусмотрены анонимные идентификаторы без команды и её места.

| Настройка | Назначение |
|---|---|
| `SERVICE` | Роль Host: `tournament`, `scores` или `results` |
| `DB`, `ASPNETCORE_URLS` | Путь собственной SQLite и адрес HTTP |
| `PEER_TOURNAMENT`, `PEER_SCORES`, `PEER_RESULTS`, `PEER_SIMULATOR` | Адреса получателей событий |
| `SCORES_URL` | Адрес сервиса баллов для имитатора |
| `ACTORS` | Учётные записи `id:role:secret;...` |
| `KEY_TOURNAMENT`, `KEY_SCORES`, `KEY_RESULTS`, `KEY_SIMULATOR`, `KEY_TEAM`, `KEY_CHECKING` | Согласованные ключи отправителей; по умолчанию `<producer>-integration-demo` |
| `SIMULATOR_KEY` | Ключ управляющего API имитатора; по умолчанию `simulator-demo` |
| `ENABLE_LAB_DEMOS` | Доступность защищённых учебных отказов и пауз |

SQL-миграции находятся в [migrations](migrations). Миграция 004 автоматически переводит внутренние ключи игр в однозначный формат; существующие результаты, события и ответы команд сохраняются. При уже неоднозначных старых данных обновление откатывается с `ambiguous_legacy_game_key`; подробности — в [контрактах](docs/integration.md#идентификаторы-и-сохранённые-данные). Таблица и сроки сохраняются в SQLite; кеш хранится в памяти и восстанавливается чтением сохранённой проекции. Обработка сроков и доставка событий выполняются независимыми фоновыми циклами.

## Результаты проверки и ограничения

Сборка без ошибок и предупреждений, **53/53 тестов**, обычный HTTP-турнир и браузерное «Демо» — **200:196**. Выполнены процессные проверки Saga с перезапуском, компенсации, повторной попытки, CAP/cache и отдельная модель 2PC. Подробные фактические результаты и границы проверки: **[docs/verification.md](docs/verification.md)**.

Проект рассчитан на небольшой локальный турнир и **один экземпляр каждой роли**. Используются статические демонстрационные секреты, без OIDC/TLS; запуск в открытом интернете требует отдельной подготовки. Рабочие сервисы команд и проверок, выдача задач и полноценный интерфейс жюри остаются внешними интеграциями по заданию. Достоверность конечных манифестов — обязательство team/checking; конфликты видны в защищённой диагностике. Контейнерный запуск и нагрузочные испытания здесь не выполнялись.

Исходная схема: [Miro](https://miro.com/app/board/uXjVHicXXYY=/); сохранённые связи — [docs/source-edges.json](docs/source-edges.json).
