# Турнир математических игр

Три отдельных C# / ASP.NET Core процесса: **турнир и участие** (:5101), **баллы и онлайн-таблица** (:5102), **итоги** (:5103). Четвёртый процесс (:5104) — тестовый имитатор team/checking. SQLite-файл у каждого свой; HTTP outbox/inbox, сохраняемые сроки, SSE. Полный исходный код находится в `src`, тесты — в `tests`.

## Подготовка к защите

Полный пошаговый показ: [docs/defense.md](docs/defense.md). Реализованы сохраняемая Saga подготовки игры с компенсацией, версионируемый кеш публичной таблицы, сценарий недоступной связи, 32 порядка доставки и отдельная учебная модель 2PC. Основной турнир и регламент сохранены.

```powershell
dotnet restore MathTournament.sln
dotnet test tests/Tests.csproj
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -BasePort 7101
```

Открыть http://localhost:7102 и нажать «Демо». Ожидается **200:196**. Порты по умолчанию — 5101–5104; `-BasePort` позволяет не мешать другой копии. Остановить: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop.ps1`.

```powershell
python scripts/lab-demo.py all --base-port 7101
python scripts/check-lab.py
dotnet run --project src/TwoPhaseLab/TwoPhaseLab.csproj
python scripts/check-commits.py
```

Отказы и приостановки доступны только при `ENABLE_LAB_DEMOS=1` и с авторизацией. Локальный скрипт включает учебный режим; `-DisableLabDemos` отключает его. Резерв таблицы и бланков не виден как активная игра до GameStarted. При компенсации интерфейс показывает отмену; повтор разрешён только после освобождения обоих резервов. SQL-миграции 002/003 обновляют прежнюю БД без удаления данных.

## Интерфейс «Математическая арена»

После запуска откройте [http://localhost:5102](http://localhost:5102). Интерфейс встроен в C#-проект: отдельный Node.js-сервер, установка frontend-пакетов и внешние шрифты не нужны.

Для прямой ссылки на конкретный турнир используйте `http://localhost:5102/?tournament=<идентификатор>`. Разделы также имеют ссылки: `#overview`, `#teams`, `#games`, `#table`, `#results`.

- **Обзор:** состояние турнира, количество команд, программа игр, таймеры и краткая таблица.
- **Команды:** регистрация ровно четырёх участников от учётной записи капитана; составы видны организатору.
- **Игры:** создание, изменение и удаление до старта; условия, эталоны, баллы, множители и сроки; последовательный запуск.
- **Онлайн-таблица:** живые результаты, выбор игры, поиск команд, четыре предусмотренных цвета вердиктов, выгрузка CSV.
- **Итоги:** победители, игровые очки и общий зачёт; до завершения отображается промежуточный результат.

Начальный режим — **Зритель**. Кнопка учётной записи внизу левого меню позволяет выбрать демонстрационного организатора, одного из двух капитанов или ввести свой токен. Изменения проверяются на сервере. Токен хранится в sessionStorage текущей сессии браузера; выбранный турнир — в localStorage.

Для защиты нажмите **«Демо» → «Запустить демонстрацию»**. Создастся новый турнир с двумя командами и двумя играми, имитатор отправит вердикты в обратном порядке, сервисы рассчитают баллы и завершат турнир. Время — около 45 секунд. Ожидается **Интеграл — 200**, **Квадрат мысли — 196**. Во время сценария можно переключать разделы и наблюдать изменения. Демонстрационный режим явно обозначен; это не реальные решения команд.

Интерфейс работает через `/ui-api/tournament/...` на том же адресе: шлюз передаёт команды сервису турнира с пользовательским токеном и проверкой Revision. `/ui-api/fixtures/{id}/{game}` вызывает отдельный тестовый имитатор и доступен только организатору. Эти маршруты не заменяют REST API трёх сервисов. Сроки обрабатывает независимый DeadlineWorker; outbox доставляется по получателям с сохраняемой задержкой повторов.

Браузерная проверка: `python scripts/check-ui.py` при запущенных четырёх процессах. Для этой дополнительной проверки нужны Chrome/Edge и Python-пакет `websocket-client` (самому приложению они не требуются). Скриншоты и отчёт сохраняются в `test-results/ui-*`.

## Локальный запуск Windows

Нужны .NET SDK 8 и Python 3.10+ (только для сценария). Выполнять из каталога MathTournament:

```powershell
dotnet restore src/Host/Host.csproj
dotnet restore src/Simulator/Simulator.csproj
dotnet restore tests/Tests.csproj
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1
python scripts/demo.py
```

Откройте [онлайн-таблицу](http://localhost:5102) и выберите demo в списке турниров. Полный сценарий займёт около 30 секунд: две команды по четыре человека, две последовательные игры, первичные вердикты, удовлетворённая и отклонённая апелляции, обратный порядок доставки, повтор событий, автоматическое закрытие, начисление очков и завершение. Ожидается A=200, B=196. Результат сохраняется в `test-results/http-scenario.json`. Для следующего запуска: `python scripts/demo.py demo2`, затем в таблице введите demo2.

```powershell
dotnet test tests/Tests.csproj --logger "trx;LogFileName=tests.trx" --results-directory test-results
python scripts/check-http.py
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop.ps1
```

Данные сохраняются между запусками. Не запускайте второй экземпляр на занятых портах. `data/processes.json` хранит PID процессов, `logs` — журналы. После остановки можно сохранить или переименовать `data` для отдельного чистого демонстрационного запуска.

## Docker Compose

```sh
docker compose up --build --wait --wait-timeout 180
python scripts/demo.py
docker compose --profile test run --rm tests
docker compose logs
docker compose down
```

Порты те же; SQLite хранится в четырёх именованных volumes. `down` сохраняет данные. Docker здесь отсутствует, поэтому команды Compose подготовлены, но фактически не выполнялись.

## API и конфигурация

[OpenAPI](docs/openapi.json) доступен также через `/openapi.json` каждого основного сервиса. Документ отмечает принадлежность маршрутов роли; не каждый маршрут доступен на каждом порту. В POST создания передайте demo/tournament.json. Изменяющие запросы требуют `Idempotency-Key`; после создания также `If-Match` с текущей Revision из организаторского GET. API возвращает предметные причины отказа `{ "code": "..." }` и 400/403/404/409/428. Списки причин есть в исходном Engine.cs и integration.md.

Тестовые bearer-токены: organizer-demo, captain-a-demo, captain-b-demo. Организаторская конфигурация ACTORS: `id:role:secret;...`. Команда регистрируется только своим капитаном, который входит в четыре уникальных участника; повтор участника между командами запрещён. Только создавший турнир организатор может менять игры, публиковать и запускать его. Открытый GET не показывает эталоны, участников и приватные связи решений. Внутренние интеграционные ключи `KEY_TOURNAMENT`, `KEY_SCORES`, `KEY_RESULTS`, `KEY_TEAM`, `KEY_CHECKING` по умолчанию `<producer>-integration-demo`; имитатор дополнительно `SIMULATOR_KEY=simulator-demo`. Это демонстрационные секреты, перед внешним размещением замените их согласованно во всех контейнерах.

Переменные: SERVICE=tournament/scores/results; DB=путь SQLite; ASPNETCORE_URLS; PEER_TOURNAMENT/SCORES/RESULTS/SIMULATOR=базовый HTTP URL; SCORES_URL у имитатора. Каждый сервис запускается одним Host.dll с собственной ролью. Пример без скрипта: `SERVICE=scores DB=data/scores.db ASPNETCORE_URLS=http://localhost:5102 dotnet src/Host/bin/Debug/net8.0/Host.dll` в shell с такой поддержкой переменных окружения.

## Правила

По прямому разрешению пользователя выбраны: верное решение = стоимость × множитель, неверное = 0 в демо; бланки normal ×1, enhanced ×1.5, risk ×2. Все значения хранятся в GameConfig, не зашиты в обработчик. При равенстве — места 1,1,3, одинаковые очки за равные игровые места, совместные победители по сумме турнира. Очки за место строго `100 − 2 × (место − 1)`. Начисление каждой игры уникально; апелляция заменяет исходный результат.

## Подробности и ограничения

[Архитектура и соответствие процессу](docs/architecture.md), [контракты внешних сервисов и анонимность](docs/integration.md), [связи исходной доски](docs/source-edges.json), [миграция](migrations/001_initial.sql). Сервисы работы команды и проверок намеренно представлены контрактами и отдельным имитатором; их рабочие интерфейсы не реализованы. SSE передаёт актуальный снимок каждые 500 мс при изменениях и восстанавливается после переподключения. Готовность итогов требует двух закрытий и совпадения манифестов со всеми применёнными вердиктами.

Реализация рассчитана на небольшой локальный турнир: SQL-снимок состояния, один экземпляр роли, статические секреты, без OIDC/TLS и автоматического исправления конфликтов. .NET 8 используется из-за установленного SDK; перед промышленным вводом нужен переход на поддерживаемую .NET LTS и актуальные пакеты. Достоверность финальных манифестов — обязательство team/checking. Необработанные конфликты видны в `/internal/diagnostics` с токеном организатора и блокируют итог игры до запечатывания. Реальные правила выдачи следующих задач остаются в team.
